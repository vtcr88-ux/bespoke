## Overall Impression

The storefront has a usable catalog skeleton and a coherent token base, but it is still visually between two identities: a soft wellness storefront and the newer "Curated Luxury Catalog" direction. The largest opportunity is to make the first viewport and product grid feel curated, restrained, and purchase-ready without turning the page into an admin dashboard.

## What's Working

- The shared design system gives the app a stable base: focus outlines, button loading, badges, fields, skeletons, and empty states are already present.
- The catalog path is complete: home preview, catalog filters, product detail, cart, WhatsApp path, checkout, support, and privacy all exist.
- The header/cart architecture is fundamentally right for a catalog: brand at left, nav in the center, cart available at right, and mobile menu support.

## Priority Issues

### P1: The hero works like a poster, not a luxury catalog entry point

**Why it matters:** The DESIGN.md says the catalog is not a poster, but the current hero uses a 760px/78svh image block and an 8rem heading ceiling. It also renders an empty `hero__badge`, has no primary action, and delays the product grid until after a very large brand moment.

**Evidence:** `apps/web/src/app/App.tsx:148-160`; `apps/web/src/styles/storefront.css:168-220`.

**Fix:** Remove the empty badge, cap hero display type near 6rem, reduce the hero footprint, add a precise catalog CTA, and keep a visible hint of the product grid in the first viewport.

**Suggested command:** `$impeccable layout apps/web/src/app/App.tsx`

### P1: Storefront-only pill buttons split the component vocabulary

**Why it matters:** The design-system contract says 8px buttons; storefront `.store-button` uses `border-radius: 999px`. This makes the web surface feel like a separate marketing theme instead of the same premium system as admin.

**Evidence:** `packages/design-system/src/ui.css:1`; `apps/web/src/styles/storefront.css:266-299`; `apps/web/DESIGN.md:164-168`.

**Fix:** Replace storefront pill CTAs with the shared `Button` vocabulary or restyle `.store-button` to the same 8px shape, state behavior, and weight.

**Suggested command:** `$impeccable polish apps/web/src/styles/storefront.css`

### P1: Catalog cards are functional but not yet exclusive

**Why it matters:** The product card is the core catalog object. Right now every card has the same shape, soft shadow, ivory image well, badge, title, subtitle, price, and icon-only plus button. It reads as a competent grid, not a curated luxury selection.

**Evidence:** `apps/web/src/app/App.tsx:306-320`; `apps/web/src/styles/storefront.css:425-480`.

**Fix:** Make image wells quieter and whiter, reduce default shadow, elevate only on hover, improve product-name hierarchy, and replace the plus-only action with a clearer add affordance on touch/mobile.

**Suggested command:** `$impeccable bolder apps/web/src/app/App.tsx`

### P1: Checkout lacks the reassurance expected from a premium purchase

**Why it matters:** Checkout is where exclusivity either becomes trust or evaporates. The current page shows "Checkout Pro", three fields, WhatsApp before CEP, and payment after CEP, but no order summary, no reassurance, no step structure, and limited recovery guidance.

**Evidence:** `apps/web/src/app/App.tsx:483-524`; `apps/web/src/styles/storefront.css:749-763`.

**Fix:** Add a checkout summary/review panel, rename "Checkout Pro", sequence contact/shipping/payment more clearly, and add concise trust/recovery copy.

**Suggested command:** `$impeccable harden apps/web/src/app/App.tsx`

### P2: Filters create useful control but weak catalog luxury

**Why it matters:** The filter panel borrows admin structure, but the visible choice set plus collapse rail can feel operational. There is no clear "clear filters" or applied-filter summary, so users must remember state from fields.

**Evidence:** `apps/web/src/app/App.tsx:218-259`; `apps/web/src/styles/storefront.css:525-570`.

**Fix:** Add applied filter chips, a clear-all action, quieter collapsed state, and make mobile filters behave like a focused drawer rather than a full-screen interruption.

**Suggested command:** `$impeccable clarify apps/web/src/app/App.tsx`

## Persona Red Flags

**Casey (Distracted Mobile User):** The hero can take most of the first mobile viewport (`78svh`), pushing the catalog down. Product-card add is an icon-only plus, which is efficient but not reassuring for a first purchase. Filters become a full-screen layer on mobile, which can interrupt browsing.

**Riley (Stress Tester):** Empty and error states exist, but recovery is generic. Long product names/subtitles may strain the fixed card body. Checkout has no obvious review step or contextual validation for CEP/phone formatting.

**Jordan (First-Timer):** The homepage does not offer a clear first action in the hero. The blank hero badge looks broken. Terms like "SKU" and "Checkout Pro" assume context the customer may not have.

**Sam (Accessibility-Dependent User):** Focus styles and icon-button labels are a strength. Risk remains around meaning conveyed by active nav underline/color and the plus-only add action being visually ambiguous.

## Minor Observations

- The `.band` styles still define a green/teal section that conflicts with the black-white-champagne direction if reused.
- The footer line "Voce e exclusivo para nos." is a good intention but too literal; it can sound less premium than the brand wants.
- The fallback hero image is a generic wellness/spa image and may reinforce the artisanal/wellness mood.
- The catalog uses "Pesquisa" for collapsed filters; "Filtros" may be clearer.
